Reproducer:
  python python/examples/gluon/05-moe-bmm1-fused-gather.py
  pytest -q -s --tb=short 'python/examples/gluon/05-moe-bmm1-fused-gather.py::test_op[128-c0]'

Kernel:
  actual Gluon `_topk_forward`

Issue:
  The topk index lowering converts two elementwise transforms of the same
  `%y_indices` tensor independently across the same layout change:

    %y_div = arith.divui %y_indices, %c32
    %y_rem = arith.remui %y_indices, %c32
    %y2 = ttg.convert_layout %y_div
    %y_onehot = arith.shli %c1, %y_rem
    %y3 = ttg.convert_layout %y_onehot

  Both conversions use the NVIDIA shared-memory swizzling path, so this emits
  two shared-memory exchanges even though layout conversion is only an element
  permutation.

Exactness:
  For unsigned i32 values and a power-of-two divisor `d`, permutation commutes
  with both operations used here:

    layout(x / d) == layout(x) / d
    layout(1 << (x % d)) == 1 << (layout(x) % d)

  The lowering therefore transfers `%y_indices` once and rebuilds the `divui`
  and one-hot value elementwise after the transfer.  No floating-point or
  approximate operation is changed.
