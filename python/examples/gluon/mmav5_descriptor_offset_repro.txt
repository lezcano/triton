Reproducer:
  python -m pytest -s --tb=short \
    'python/examples/gluon/01-attention-forward.py::test_op[1cta-False-dtype0-False-64-1024-32-1]'

Issue:
  MMAv5 shared-memory descriptors encode the base address in 128-bit units.
  The lowering formed each descriptor from a byte pointer after adding a static
  shared-memory offset, so PTX repeated shifted extracts for aligned offsets
  that are exact additions in descriptor units.

Before PTX:
  bfe.u32   %r110, %r42, 4, 14;
  add.s32   %r111, %r42, 32768;
  bfe.u32   %r112, %r111, 4, 14;
  add.s32   %r113, %r42, 16384;
  bfe.u32   %r114, %r113, 4, 14;
  add.s32   %r115, %r42, 49152;
  bfe.u32   %r116, %r115, 4, 14;

After PTX:
  shr.u32   %r110, %r42, 4;
  bfe.u32   %r111, %r42, 4, 14;
  add.s32   %r115, %r110, 1024;
  and.b32   %r116, %r115, 16383;
  add.s32   %r117, %r113, 1024;
  and.b32   %r118, %r117, 16383;

Reasoning:
  For a 16-byte aligned static offset `16 * k`, descriptor base extraction is
  bitwise exact under:
    (((base + 16 * k) >> 4) & 0x3fff)
      == (((base >> 4) + k) & 0x3fff)
  including 32-bit wraparound. The lowering now peels aligned static shared
  offsets and adds them after the shift in descriptor units.

Effect:
  Hand-editing the emitted PTX first reduced normalized `nvdisasm -c` lines
  from 2732 to 2724. Compiling the checked-in attention specialization from
  source after the lowering change preserves the same final SASS reduction:
  dump SASS lines fall from 2654 to 2646 and cubin size from 230120 to 229920
  bytes.

Additional carry-free descriptor packing:
  checked-in wgrad specialization:
    `python/examples/gluon/02-conv-wgrad.py`:
    `test_op[conv2d_wgrad_fixed-1-128-64-64-128-1-1-1-0]`

  The same MMAv5 descriptor lowering also formed four descriptors from one
  14-bit dynamic base with separate 64-bit additions.

Before PTX:
  bfe.u32 %r255, %r253, 4, 14;
  cvt.u64.u32 %rd16, %r255;
  or.b64  %rd8,  %rd16, 4611756662083026944;
  add.s64 %rd10, %rd16, 4611756662083027072;
  add.s64 %rd12, %rd16, 4611756662083027200;
  add.s64 %rd14, %rd16, 4611756662083027328;

After PTX:
  bfe.u32 %r255, %r253, 4, 14;
  mov.b32 %r1093, 1073758272;
  add.u32 %r1094, %r255, 33554432;
  mov.b64 %rd8, {%r1094, %r1093};
  add.u32 %r1096, %r255, 33554560;
  mov.b64 %rd10, {%r1096, %r1093};

Reasoning:
  The dynamic descriptor base is masked to `0x3fff`. The low descriptor words
  in this family are `0x02000000`, `0x02000080`, `0x02000100`, and
  `0x02000180`; even the largest sum is only `0x0200417f`. Because no low-word
  add can carry into bit 32, packing `{low_add, high_const}` is bitwise
  equivalent to the original 64-bit descriptor add.

Effect:
  Hand-editing the current emitted PTX first reduced final SASS instructions
  from 2424 to 2416 and `UIADD3.X` carry instructions from 13 to 1 for the
  checked-in wgrad specialization. Source lowering now emits the same
  carry-free packing form when the low-word addition is proven not to carry.
