Reproducer:
  python -m pytest -s --tb=short \
    python/examples/gluon/04-2cta-block-scale-matmul.py::test_mma_scaled_warp_specialized[2-256-256-4-mxfp8-mxfp8-128-128-128]

Target:
  NVIDIA GB300

Issue:
  The NVIDIA lowering left tensor `arith.truncf` from `f32` to `f16` as
  scalar `llvm.fptrunc`. In the block-scale epilogue, native LLVM later
  recovered vector `<2 x float> -> <2 x half>` truncations from the TMEM-load
  results, but `llc` emitted each pair through a redundant 64-bit pack/unpack
  round trip before the packed PTX conversion.

Before PTX:
  mov.b64 %rd43, {%r284, %r285};
  mov.b64 {%r547, %r548}, %rd43;
  cvt.rn.f16x2.f32 %r549, %r548, %r547;

After PTX:
  cvt.rn.f16x2.f32 %r545, %r289, %r288;

Reasoning:
  The custom NVIDIA `arith.truncf` lowering still lowers one source op at a
  time, but consumes two adjacent result elements from that one op and emits
  the packed PTX conversion directly. The deleted `mov.b64` instructions were
  only bit copies, and the surviving conversion uses the same `cvt.rn`
  operation with the same two input bit patterns in the same order, so the
  transformation is bitwise-equivalent.

Effect:
  Recompiling the checked-in block-scale specialization from source emits the
  direct packed PTX form. On GB300, executable SASS instructions reported by
  `nvdisasm -c` drop from 1328 to 1320 for this specialization.
